# 海悅廣告｜土地評估系統

這個專案的正式目標不是「貼上 ChatGPT 文字再整理報告」，而是建立一套真正可公開使用的土地評估網頁應用程式。

## 正式產品目標

### 1. 公開使用者

任何人只要拿到公開連結，都可以使用。

使用流程：

1. 開啟土地評估系統連結。
2. 輸入基本資料：
   - 配合業主
   - 標的地號
   - 調研日期
   - 土地售價（可空白）
   - 指定競案（可空白）
3. 點擊「開始調研」。
4. 系統自動依地號完成土地評估調研。
5. 系統產出完整土地評估報告。
6. 使用者可預覽報告。
7. 使用者可輸出 PDF。
8. 一般使用者不可輸出 Word。

### 2. 戴異軒本人

只有戴異軒本人可以輸出 Word 檔做後續修改。

使用流程：

1. 以專屬帳號登入。
2. 輸入地號並產出土地評估報告。
3. 可輸出 PDF。
4. 可輸出 Word / DOCX。
5. 可下載後進行修改。

## 權限規則

| 功能 | 公開使用者 | 戴異軒本人 |
|---|---:|---:|
| 輸入地號 | 可 | 可 |
| 自動產出報告 | 可 | 可 |
| 預覽報告 | 可 | 可 |
| 輸出 PDF | 可 | 可 |
| 輸出 Word | 不可 | 可 |
| 修改報告內容 | 不可或僅暫存 | 可 |

## 重要技術限制

目前這個 repo 使用 GitHub Pages 靜態部署。

GitHub Pages 只能提供前端靜態網頁，無法安全完成以下功能：

- OpenAI / ChatGPT API key 保護
- 後端網路搜尋
- 內政部實價登錄資料整理
- 都市計畫／學區／里別資料查詢
- 使用者登入與身分驗證
- 判斷誰是戴異軒本人
- 安全限制 Word 下載權限
- 後端產生 DOCX 檔案

因此，正式版不能只靠 GitHub Pages。正式版需要後端服務。

## 建議正式架構

### Frontend

- Next.js 網頁介面
- 公開輸入表單
- 報告預覽
- PDF 輸出
- 登入狀態判斷
- Word 按鈕權限顯示

### Backend

建議使用：

- Vercel Functions / Next.js API Routes
- 或 Supabase Edge Functions
- 或 Render / Railway 後端服務

後端負責：

- 接收地號
- 執行 AI 調研
- 串接公開資料來源
- 產生完整報告資料
- 產生 PDF / DOCX
- 權限驗證

### AI / 調研引擎

後端需串接 OpenAI API 或其他 AI 服務，並依固定調研邏輯產出土地評估內容。

### Auth / 權限

建議使用：

- Supabase Auth
- Clerk
- NextAuth

權限規則：

- 一般使用者：只可輸出 PDF。
- owner / admin role：可輸出 Word。
- 戴異軒帳號需被標記為 owner。

## 固定調研欄位

報告需固定包含以下內容：

- 配合業主
- 調研時間
- 標的位置
- 標的地號
- 土地分區
- 基地面積
- 法定建蔽率
- 法定容積率
- 臨路條件
- 土地售價
- 學區
- 里別
- 基地四向現況
- 交通動線
- 生活機能
- 公共建設
- 區域銷況
- 建議產品
- 個案參考
- 價格預判
- 綜合評估
- 資料來源與待複核事項

## 調研原則

所有資料仍需以實際狀況與公開資料查詢為基礎，但每一欄都應盡量主動查出明確答案，不應大量填寫「待複核」。

只有在公開資料確實不足、資料矛盾或需正式文件確認時，才標註：

- 待複核
- 依公開資料初判
- 依業主資料初判
- 待戶政／教育局／分區證明複核

並需說明待複核原因。

## 報告署名規則

報告正文內不顯示「設計人」。

但列印 PDF 或輸出檔案時，報告底部需固定保留：

```text
海悅機構｜海宇國際 戴異軒 製
```

此署名不應放在可編輯正文欄位內。
